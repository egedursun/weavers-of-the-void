## Method and general findings

- Wiring: every one of the 92 phases in EXPORTED_PHASES appears in TICK_ORDER, TRANSITION_ORDER, PRE_ or POST_TRANSITION_ORDER (engine/core/test_wiring.py enforces this). world_age is not a phase but is called from doom_clock. No orphan engine phase was found.
- Depth of verification differs by area. Read in full against the legacy function: heroism and monsters (sim.js kahramanlik, canavar baskini), curses, population growth and capacity, doom clock and creator essence (sim.js cagGecisi), warfare battle power and siege (derin.js seferler), creatures (yaratik.js yaratikMotoru), mortal agent selection and turn (olumluler.js), rules service (denge.js dengeAyarla), civilization phase structure. For the remaining rows (society economy, births, dark ages, espionage, wonders, religion spread, culture exchange, climate, god death, travel-adjacent rows) the new code was identified by phase and function, its structure and rule usage were skimmed, and the test that exercises it was checked by name; line-by-line formula comparison was not done for those. Formulas, caps and orders that were compared match; documented deviations are decisions 16, 35, 39, 40, 50, 52, 53, 54, 56. Undocumented deviations found: CRE-007, RULE-006, RULE-007, DATA-001, DATA-029.
- Manual controls: 212 player actions exist (services/player/catalog.py ACTIONS) and the frontend command palette (features/command-palette) lists the whole catalogue through GET /api/actions, so every action has a UI surface. The gaps are the controls the matrix names that have no action or route at all (list below).
- Test standard applied: a row is IMPLEMENTED only when a test calls the code path and asserts its effect. Branches that exist in code but are reached by no test are PARTIAL with the branch named. Test function names in the JSON were verified to exist.

## Cross-cutting gaps

1. No run-a-phase-now control. pipeline.py has run_named_phase and find_phase, but nothing calls them: there is no /api/engine/phases/{phase}/run route and no frontend caller. Affects ENG-001, 009, 012, 034, 035, 037, 038, 042, 047, 055, 079, DEEP-029, DEEP-032. Phase on/off switches do exist as rules engine_phases.* (editable in the world rules screen).
2. Community relations are invisible to the player. relation_list, relation_history and the stored relation value, blood-feud start and event history are read only by LLM tool views. EntityRelations.tsx shows bonds only. There is also no action to set a relation value or declare a blood feud (only feud:end). Affects DEEP-012, 024, 025, 027, 028.
3. No manual integrity, dead-bond sweep or database-optimize trigger. DataRepairs.startup runs only at startup and on world_changed; DataRepairs.run is never called; ENG-072 also requires re-running after every death. Affects ENG-072, DEEP-006, 007, 014, 171, DATA-027, DATA-028.
4. War state has no player-facing read model: battles, armies, sieges and captives are written (BattleRow, ArmyRow, SiegeRow, CaptiveRow) but no router lists them and the proposed WarsPanel was never built. Affects DEEP-072 and DEEP-031 (heroes of a community).
5. Mortal agent inspection: GET /api/entities/{id}/agent-context and a tool catalogue view do not exist (MORT-021, MORT-023).
